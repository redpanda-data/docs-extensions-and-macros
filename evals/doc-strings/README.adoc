= Doc-strings evals: execution-verified model behaviors
:toc:
:toc-placement!:

Evals for the four MODEL-DRIVEN behaviors that the doc-strings GitHub
workflows delegate to Claude. The deterministic tools themselves
(`tools/lint-strings`, `tools/preview-string`, `tools/overrides-audit`) are
covered by the jest suite and are NOT re-tested here - they are the
*measuring instruments* these evals use to grade the model.

A separate `--doc-impact` mode scores the workflow's published-content
impact pass against labeled PRs; see <<_doc_impact_assessment>>.

toc::[]

== The philosophy: execute, never grade prose

The failure mode this harness exists to avoid: evals whose assertions are
regex matches over model prose. Those pass without exercising anything and
cannot meaningfully fail.

Every verdict here is computed by *executing* the model's output against the
real machinery:

1. A fixture mini-repo (shaped like redpanda: `src/v/config/`, `*probe.cc`,
   `src/go/rpk/pkg/cli/`) is materialized in a temp dir.
2. The real tools produce the genuine input the production workflow would
   feed the model (`doc-tools lint-strings --format json` findings, or a
   `doc-tools overrides audit` candidate row).
3. The model is called headless (`claude -p`, no tools, prompt on stdin,
   300s timeout) with a prompt that mirrors the production workflow prompt
   plus a machine-parsed output contract.
4. The harness *applies* the output - a GitHub `+```suggestion+` block
   replacing the finding's `line_start..line_end`, or a `LINES a-b` +
   `+```replacement+` span edit - to the fixture file.
5. The verdict is re-computed mechanically:
   * re-run `lint-strings`: the rewritten declaration must have **zero
     findings of any severity**, and every untouched declaration must keep
     exactly the findings it had (fingerprint compare);
   * re-run the surface extractor (the real Python property extractor, the
     metrics scanner, the rpk scanner): the target must still parse, every
     other declaration must be byte-identical, and every non-description
     field of the target must be unchanged;
   * for upstream ports, re-run `overrides audit`: the classification must
     flip (`UPSTREAMABLE -> REDUNDANT`, `SPLIT -> KEEP`), which is the
     production definition of "the port worked";
   * blanked-literal structural compare: string-literal contents are
     blanked, adjacent literals merged, whitespace neutralized - the result
     must be identical before/after, proving the model changed *no token
     outside the doc string* while still allowing clang-format re-wrapping;
   * C++ suggestions must keep every line within 80 columns.

No check ever asks "does the model's answer *sound* right". The only prose
inspection anywhere is fence parsing and the literal `NO_SUGGESTIONS`
sentinel in a negative control - both structural.

== The four behaviors under test

[cols="1,2,3"]
|===
|Behavior |Production home |Eval cases

|A. Suggestion rewrite
|`doc-strings-review.yml` (redpanda, redpanda-operator): Claude turns
deterministic lint findings into GitHub suggestion blocks
|`prop-empty-description`, `prop-tautology-no-period`, `metric-name-echo`
(rewrite must carry NO terminal period), `rpk-flag-lowercase-period` (only
the usage literal may change - the rest of the line is byte-compared)

|B. Upstream port
|`upstream-doc-strings.yml`: Claude ports override prose into the C++
source string it masks. NOT YET BUILT - no such workflow exists in this repo
or the docs repo, so behavior B is currently exercised only by these evals.
The evals are the contract the workflow will have to meet.
|`upstream-clean` (UPSTREAMABLE text lands verbatim), `upstream-split`
(SPLIT candidate: stripped prose lands, the xref must NOT reappear -
`detectDocsMarkup` over the re-extracted string must be empty)

|C. False-positive guard
|Both workflows' suggest-only posture
|`negative-property-diff` (conforming rewording diff -> zero suggestions,
zero doc-impact claims), `negative-metrics-file` (conforming probe file ->
the model must claim `{"findings": []}`). *Any* invention fails the case.

|D. Prose quality
|`doc-strings-review.yml`'s prose-quality pass (added in #297): the Claude
pass is gated on declarations the PR TOUCHED, not on lint findings, because
a string can satisfy every mechanical rule and still tell an operator
nothing.
|`prose-vacuous-clean` (a lint-clean but vacuous rewording: the model must
suggest a rewrite that restores substance, and the applied result must still
lint clean), `terminology-misuse` (a lint-clean, substantive description that
lowercases the product name, which `terminology.md` names as incorrect: the
model must suggest the canonical casing). Both sabotage against the fully
conforming rewording `negative-property-diff` uses, where staying silent is
correct and so fails the must-suggest check.
|===

== Negative controls that provably can fail

A negative control that cannot fail is decoration. `--sabotage <id>` re-runs
a negative control against a deliberately violating fixture (defined per
case as `sabotageEdits`), skips the zero-findings precondition, and *expects
the case to FAIL*:

[source,bash]
----
node evals/doc-strings/run-evals.js --sabotage negative-property-diff
node evals/doc-strings/run-evals.js --sabotage negative-metrics-file
----

Exit 0 means the proof succeeded (the model flagged the planted violation
and the harness caught it as a FAIL verdict); exit 1 means the harness can
no longer catch invented findings and must be fixed. Nothing is edited on
disk, so there is nothing to restore afterwards.

Both proofs were run against the live model when this harness landed; both
controls demonstrably fail on violating input.

== Running

[source,bash]
----
npm run eval:doc-strings                     # full suite (10 cases)
node evals/doc-strings/run-evals.js --case metric-name-echo
node evals/doc-strings/run-evals.js --model opus
node evals/doc-strings/run-evals.js --keep-temp   # keep fixture repos
----

Requirements:

* The `claude` CLI on PATH and authenticated. When it is missing the suite
  prints `SKIPPED` and exits with code 3 - a skipped run never looks green.
* The property-extractor venv (`tools/property-extractor/tmp/...`). It is
  created automatically on the first properties run (see
  `tools/lint-strings/surfaces/properties.js`).

Exit codes: `0` all pass (or sabotage proven), `1` failures, `2` harness
error, `3` skipped.

Deliberately **not wired into CI**: a full run makes ten real model calls
(a few minutes of wall time and real tokens). Run it when the workflow
prompts, the lint rules, or the extraction change.

Each run writes `results/<timestamp>/<case>/` with the exact prompt, the raw
model output, before/after fixture snapshots, and `evidence.json` (every
mechanical check with its measured detail). `results/` is gitignored.

== Anatomy

[cols="1,3"]
|===
|`run-evals.js` |Driver + per-kind executors (rewrite, upstream,
negative-review, negative-audit). CommonJS, zero new dependencies.
|`cases.js` |Declarative case table. Every positive case pins
`expectRules` / `expectClassBefore` preconditions that are asserted against
the REAL tool output before the model is called - fixture drift aborts as
`HARNESS_ERROR` instead of silently testing something else.
|`prompts.js` |Prompt templates mirroring the workflow prompts
(`doc-strings-review.yml`, which ships here, and the not-yet-built
`upstream-doc-strings.yml`) plus the per-surface
contract from the doc-strings skill, and a machine-parsed OUTPUT CONTRACT
section (the one deliberate delta from production, which posts via MCP
instead).
|`lib.js` |Fixture materialization, real doc-tools invocations, fence
parsing, and the mechanical comparators (blanked-literal normalization,
extraction diffing, finding fingerprints).
|`fixtures/conforming_probe.cc` |Fully conforming metrics file for the
negative control. The harness asserts its zero-findings precondition on
every run, so drift cannot silently blunt the control.
|===

Fixture mini-repos are copied from `tools/lint-strings/fixtures/` (the same
known-bad/conforming sources the jest suite pins) and edited per case with
exact-match `find`/`replace` pairs that throw when they no longer match.

== Adding a case

1. Add an entry to `cases.js`:
   * `rewrite` kind: pick (or `edits`-create) a declaration in a fixture
     that the real linter flags, set `target` and `expectRules`, and for Go
     one-liners set `singleLine: true` (enables the byte-identical
     prefix/suffix check).
   * `upstream` kind: provide the `overrides` document, `expectClassBefore`
     (what the real audit must say going in) and `expectClassAfter` (what it
     must say after a correct port).
   * negative kinds: provide a conforming fixture (or `diffEdits`) AND
     `sabotageEdits` that plant a violation - a negative control without a
     sabotage path is not accepted, because it cannot prove it can fail.
2. Run the single case: `node evals/doc-strings/run-evals.js --case <id>`.
3. If it is a negative control, prove it: `--sabotage <id>` must exit 0.

Iteration rule (the honest-eval contract): when a positive case fails on a
legitimate model shortcoming, tighten the *prompt template* - that is the
eval doing its job of hardening the production prompt. Never weaken a
mechanical assertion to make a case pass. Comparator changes are only
acceptable when the assertion was measuring something the contract
explicitly permits (for example, clang-format re-wrapping), and must keep
every genuine token change failing.

== Doc-impact assessment

The PUBLISHED-CONTENT IMPACT pass of `doc-strings-review.yml` decides, per
engineering PR, whether a published page outside the generated references
is now wrong or missing. When it is, the pass writes `doc-impact.json` and
the workflow dispatches it to the docs team's Jira router, which opens a
ticket. The `--doc-impact` mode scores that decision against labeled PRs.

=== What a run does

For each item, the harness:

. Writes the frozen inputs into an empty working directory:
  `pr-diff.patch` and `lint-findings.json` (built the way the workflow
  builds them) and `pr-view.json` (the PR title and description).
. Builds the prompt from the live workflow: the input description (from
  "You are reviewing" to INLINE SUGGESTIONS) and the PUBLISHED-CONTENT
  IMPACT section, cut from `doc-strings-review.yml` at run time, plus one
  HARNESS NOTE paragraph saying only the impact pass runs and that `gh` is
  unavailable. Rewording the workflow retests the new text; deleting or
  renaming the section is a harness error.
. Runs `claude -p` with the workflow's model default, `--max-turns`,
  redpanda-docs MCP tools, `Read` and `Write`, and its disallowed tools.
  `Bash` is withheld because there is no checkout and no `gh`. The run uses
  `--setting-sources project` and `--strict-mcp-config`, so your own
  settings, plugins, hooks and MCP servers never reach it.
. Counts the item as flagged only when the run left a `doc-impact.json`
  that the dispatch step's own `jq` gate accepts. The gate is cut from the
  workflow's `Dispatch doc-impact` step, so a report production would
  discard is not a flag here either.

An item whose `lint-findings.json` has no declarations and no removed
surface lines is scored as not flagged without a model call, because the
workflow skips the pass in that case.

=== Running

[source,bash]
----
npm run eval:doc-impact                          # every confirmed item, replayed MCP
node evals/doc-strings/run-evals.js --doc-impact --controls
node evals/doc-strings/run-evals.js --doc-impact --case <id>[,<id>]
node evals/doc-strings/run-evals.js --doc-impact --json > scores.json
node evals/doc-strings/run-evals.js --doc-impact --include-unconfirmed
----

Other options: `--items <file>`, `--model <model>` (default `sonnet`, the
workflow's non-gateway model), `--keep-temp`. You need the `claude` CLI,
`jq`, and the property-extractor venv for the controls.

Exit codes: `0` the run completed (with `--controls`: both controls
behaved), `1` a control failed or a refresh failed, `2` harness or model
error on any item (its scores are incomplete), `3` skipped (no `claude`).

Each run writes `results/<timestamp>-doc-impact/<item>/` with the prompt,
the inputs, the full `stream-json` transcript, any `doc-impact.json`, the
replay log and `evidence.json`, plus a `summary.json` for the run.

=== Items

`doc-impact/items.json` is an array of objects:

[cols="1,3"]
|===
|`id` |Lowercase slug; also the name of the item's fixture and recording.
|`repo`, `pr_url` |`owner/name` and the pull request URL.
|`base_sha`, `head_sha` |Full SHAs: the PR's base and the head that was reviewed.
|`title`, `body` |The PR title and description, frozen.
|`label` |`needs_docs` or `no_change`.
|`label_strength` |`strong` or `weak`.
|`confirmed_by` |Who confirmed a weak label, or `null`.
|`expected_pages` |For `needs_docs`: the `https://docs.redpanda.com/` pages a
writer actually edited. Empty for `no_change`.
|`reason` |One line on why the label holds.
|`stacked_on` |Optional: the id of the item this PR is stacked on or follows
up, for the duplicate rate.
|===

Only items with `label_strength: strong` or a `confirmed_by` value run and
count by default. `--include-unconfirmed` runs and scores the rest.

Freeze an item's inputs once, with network access:

[source,bash]
----
node evals/doc-strings/run-evals.js --doc-impact --refresh-diffs --case <id>
----

This makes a partial clone with `gh repo clone` (private repos work with
your `gh` login), checks out `head_sha`, runs this checkout's
`doc-tools lint-strings --diff <base_sha>`, and writes the merge-base source
diff with the workflow's own pathspec excludes and size cap. The output
lands in `doc-impact/fixtures/<id>/`. Clones are cached under the system
temp directory, and the command prints where; delete it when you finish,
because clones of the large repos take real disk space. The workflow can
also skip declarations reviewed on earlier pushes; a frozen item always
covers the whole PR.

=== Recording and replaying the docs MCP server

The pass makes up to four redpanda-docs MCP calls against
docs.redpanda.com. Published pages change, so live calls make scores drift.
Runs therefore replay recorded responses by default.

* `--mcp record` runs against the live server (the workflow's
  `--mcp-config`, or your own with `--mcp-config <json|file>`), saves the
  item's MCP calls and results from the transcript to
  `doc-impact/recordings/<id>.json`, and snapshots the server's tool list
  to `doc-impact/mcp-tools.json`. Recording overwrites the item's previous
  recording.
* `--mcp replay` (the default) registers `doc-impact/replay-server.js`, a
  small stdio MCP server, under the production server name. It serves the
  snapshot tool list and answers each call from the item's recording:
** *exact*: same tool and arguments, ignoring case, whitespace, and the
   free-text `context` argument;
** *nearest*: the recorded call to the same tool whose search text shares
   the most tokens, when it shares at least half the tokens of the shorter
   query. The model rephrases its queries from run to run, and every call
   in one recording was made for the same PR;
** *miss*: an explicit `NO RECORDING` tool error.
+
Every call lands in the item's `replay-log.jsonl` with its match kind, and
the table shows nearest and miss counts per item. A miss means the run did
not see the docs it asked for: re-record that item. An item with no
recording is a harness error in replay mode.
* `--mcp live` calls the live server and saves nothing.

Anonymous access to the docs MCP server is limited to a few tool calls per
day per network address. Record a large item set from a signed-in MCP
config, or over several days.

=== Scoring

[cols="1,3"]
|===
|Flag recall F |Share of `needs_docs` items that were flagged.
|Abstention recall A |Share of `no_change` items that were not flagged.
|Headline |`2·F·A / (F + A)`. A pass that flags everything or nothing
scores 0. The harness refuses the headline when only one class is present.
|Page precision and recall |On correctly flagged items with
`expected_pages`: the overlap between the report's `affected_pages` and
`expected_pages`, micro-averaged. URLs are compared after normalization:
`https`, lowercase host without `www`, no query, fragment, trailing slash,
`.html` or `index`, and docs version segments (`current`, `beta`, `25.3`)
collapsed to one token. Redirects are not followed, so a moved page counts
as a different URL.
|Duplicate rate |Among flagged items whose `stacked_on` item was also
flagged: the share that repeat a page or a finding name of that item.
|===

Items with a harness or model error are excluded from every score and make
the run exit `2`.

=== Controls

`doc-impact/controls.json` holds two synthetic items that prove the harness
can fail. Their inputs are not frozen: the property lint fixture is
materialized, edited, committed, and passed through the real
`lint-strings --diff` and `git diff`, like the other cases in this suite.

* `control-needs-docs` renames `enable_rack_awareness`, which published
  guides tell you to set by name. It must be flagged with at least one
  expected page.
* `control-no-change` is the wording-only rewording from
  `negative-property-diff`. It must not be flagged.

`--controls` exits `0` only when both hold and no replay call missed. A
harness that always flags fails the negative control; one that never
flags, or loses the docs responses, fails the positive one. Run the controls
after any change to the prompt, the harness, or the recordings.

=== Self-test

`__tests__/evals/doc-impact.test.js` runs in the jest suite without the
`claude` CLI. It covers prompt, tool and gate extraction from the live
workflow, item validation, URL normalization, the scoring math (including
flag-everything and flag-nothing scoring 0 and the one-class refusal),
`stream-json` parsing, the replay server over stdio, and control
materialization with the real lint.
