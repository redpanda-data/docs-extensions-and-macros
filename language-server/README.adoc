= Docs language server

An LSP server for AsciiDoc pages in Redpanda docs repositories. It checks a page with the same code the build runs, so the editor and the build report the same problems in the same words.

== What it does

* Completion of property names after `prop:` and `propval:`, of `propval:` fields and `format=` inside the brackets, and of taxonomy labels on a `:page-categories:` header line.
* Hover with a property's description, type, default, limits and enterprise status; the value a `propval:` renders; and a category's definition and replacement.
* Diagnostics for an unknown or Cloud-unavailable `prop:` name, a `propval:` that would render `<unknown ...>`, and an unknown, deprecated, or untaxonomized `:page-categories:` value. `:property-validate:` in the page header is honored.
* A quick fix that rewrites a deprecated category the way `doc-tools check-metadata --fix` does.

== Where the data comes from

[cols="1,2"]
|===
|Data |Loader

|Property JSON
|`loadPropertiesFor` in `macros/prop.js`, over the minimal content catalog in `extension-utils/component-catalog.js` (the component's `antora.yml` and its `modules/reference/attachments/` property files), which `migrate-property-values` uses too. The release series comes from the `version` in `antora.yml`, exactly as in the build.

|Taxonomy
|`loadTaxonomyFrom` in `extension-utils/taxonomy.js`: the checkout's `shared/modules/ROOT/attachments/taxonomy.yml`, then `$REDPANDA_DOCS_PATH`, then the published file.

|Legacy categories
|`loadLegacyCategories` in `tools/check-metadata`.
|===

A Cloud component (`env-cloud`) has no property data of its own. Set `REDPANDA_DOCS_PATH` to a local checkout of `redpanda-data/docs` and the server reads its property JSON as the streaming component, as the build does.

== Run it

[,bash]
----
npx docs-language-server --stdio
----

* VS Code: the extension in `editors/vscode`.
* Claude Code: a plugin `.lsp.json` that runs the server for `.adoc` files:
+
[,json]
----
{
  "redpanda-docs": {
    "command": "npx",
    "args": ["docs-language-server", "--stdio"],
    "extensionToLanguage": { ".adoc": "asciidoc" }
  }
}
----

== Test it

[,bash]
----
npm run test:language-server
# The same requests against a real docs checkout:
DOCS_LS_REAL_DOCS=/path/to/docs npm run test:language-server
----
