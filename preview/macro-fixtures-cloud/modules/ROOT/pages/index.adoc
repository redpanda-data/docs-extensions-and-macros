= Cloud fixtures

Exercises the Cloud rules. This component declares `env-cloud` and publishes no
property data of its own.

== Only cloud_supported properties are available

* prop:iceberg_enabled[] is `cloud_supported: true`, so it renders marked.
* prop:log_segment_size[] is a cluster property the Cloud control plane does not
  expose, so it renders as plain code and the build says why.
* prop:fips_mode[] is a broker property. The control plane config that
  `cloud_supported` comes from describes cluster configuration only, so it has
  no opinion on broker or topic scope and the property is not gated.

== Release candidates are ignored

The build also contains `redpanda-properties-v26.3.1-rc1.json` from the beta
fixtures, which outranks the GA file by version number. Cloud must still use
the GA data, so prop:iceberg_delete_orphans_enabled[] -- which exists only in
the release candidate -- must NOT validate here.

== Enterprise features have no license concept here

Redpanda Cloud has no Enterprise Edition license, so `+enterprise:+` renders
as plain text on this page, even for a feature the registry recognizes:
enterprise:Tiered Storage[] must NOT carry the enterprise styling, tooltip,
or link it gets on a non-Cloud page (compare with the
xref:preview:ROOT:macros-showcase.adoc[macro showcase^]).

The block macro renders a warning instead of a table:

enterprise_features::redpanda[]

[[property-values-on-cloud]]
== Property values on Cloud

`propval:` reads the same GA data, with the same gate.

* propval:iceberg_enabled[type] must read "boolean".
* propval:iceberg_enabled[default] must read "<unknown default>": the Cloud
  property reference states no defaults (it shows "Available in the Redpanda
  Cloud Console"), so a Cloud page cannot state one either.
* propval:log_segment_size[min] must read "<unknown min>": the property is not
  available in Cloud.
* propval:fips_mode[scope] must read "broker": broker properties are not
  gated.

[[reference-values-on-cloud]]
== rpk and Connect values on Cloud

`rpkval:` borrows the GA rpk data from `streaming-ga-lender`, and
`connectval:` reads the `connect` component's data, both gated for Cloud.
Build with `local-macro-showcase-playbook.yml` to see these values: the full
test playbook pulls the real docs repo, which publishes no rpk attachment yet.

* rpkval:verbose[command=rpk cluster brokers] must read "<unknown default>"
  and log unavailable: `rpk cluster brokers` is self-managed only.
* rpkval:force[command=rpk shadow delete] must read "<unknown default>" and
  log cloud-hidden, because the reference scopes that command's description
  to self-managed; rpkval:force[type,command=rpk shadow delete] must read
  "bool".
* connectval:max_buffer[component=inputs/stdin] must read "<unknown default>",
  and the log must name `connect-4.114.0.json cloudSupported` as the source:
  the `stdin` input is not available in Cloud.
* connectval:client_id[introduced,component=inputs/redpanda] must read
  "<unknown introduced>": the Connect reference shows "Requires version" only
  outside Cloud.
